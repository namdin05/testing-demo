Vấn đề cần giải quyết

Tester không thiếu công cụ. Họ thiếu một mạch liên kết giữa các công cụ.

Trong một team nhỏ, requirement có thể nằm ở Jira, test case ở Google Sheets, evidence ở Drive, bug ở một tracker khác và trao đổi lại nằm trong Slack hoặc Teams.

Khi dữ liệu bị tách rời, những câu hỏi đơn giản như “requirement nào chưa test?”, “bug này xuất phát từ test case nào?” hay “release đã đủ điều kiện sign-off chưa?” trở thành công việc đối chiếu thủ công.

Công việc cụ thể hệ thống hỗ trợ

Từ lúc Dev giao build đến lúc QA sign-off.

Hệ thống không cố “quản lý mọi thứ trong testing”. Nó tập trung vào một công việc rõ ràng: quản lý vòng đời kiểm thử của từng release.

  1. 01
    R
    Requirement

    Xác định chức năng cần được kiểm chứng trong release.

  2. 02
    T
    Test design

    Thiết kế test case, dữ liệu test và expected result.

  3. 03
    ▶
    Execution

    Chạy manual hoặc nhận kết quả từ automation.

  4. 04
    !
    Defect

    Ghi nhận lỗi và giữ liên kết đến test case gốc.

  5. 05
    ↻
    Regression

    Retest bản sửa và kiểm tra ảnh hưởng liên quan.

  6. 06
    ✓
    Decision

    Tổng hợp coverage, blocker và rủi ro để sign-off.

Phạm vi đề tài

Không xây một “Testing Super App”.

Performance, security, penetration hay game testing đều có workflow và dữ liệu riêng. Proposal này cố ý khóa scope để giải quyết sâu bài toán functional/regression testing trước.

IN

Core scope

  • Functional testingKiểm chứng hành vi theo requirement.
  • Regression testingRetest và kiểm tra tác động sau thay đổi.
  • Manual executionTester trực tiếp ghi nhận kết quả và evidence.
  • Automated functional resultNhận kết quả từ Playwright / Selenium / API runner.
  • Web & Mobile softwarePhạm vi sản phẩm mục tiêu ban đầu.
OUT

Not core — for now

  • Performance testingRPS, p95/p99, throughput, resource profiling.
  • Security testingVulnerability, CVE/CVSS, remediation lifecycle.
  • Penetration testingAttack path và exploitation workflow.
  • Game-specific QABuild/device/platform matrix đặc thù game.

Giá trị mà hệ thống phải tạo ra

Mở hệ thống lên, QA Lead phải trả lời được ngay.

01

Release này đang test đến đâu?

Execution progress + run status theo release.

02

Requirement nào chưa được cover?

Traceability giữa requirement và test case.

03

Test nào đang Fail hoặc Blocked?

Trạng thái test run có thể lọc và truy nguyên.

04

Còn Critical bug nào chưa fix?

Defect status gắn trực tiếp với execution.

05

Bug này đến từ test case nào?

Trace Requirement → Case → Run → Defect.

06

Đã đủ điều kiện release chưa?

Coverage + blocker + regression + quality signal.
